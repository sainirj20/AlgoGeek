Spring Annotation Reference

A single lookup table of the Spring annotations that come up most often in interviews and day-to-day work — what layer it belongs to, what it does, where in the code it's legal to place it, and a minimal example. Click any column header to sort — click again to reverse the order. For worked examples of most of these in context, see the Spring Core, Spring Boot, Spring Web, Spring Data JPA, and Spring Security pages.

AnnotationScopeUsesApplies ToExample
@ComponentCore ContainerGeneric stereotype marking a class as a Spring-managed bean, discovered via @ComponentScan.Class@Component public class EmailValidator { }
@ServiceCore ContainerSemantic specialization of @Component for the business/service layer — purely a naming convention to Spring itself, but signals intent to readers and tools.Class@Service public class OrderService { }
@RepositoryCore ContainerSpecialization of @Component for the persistence layer; also enables automatic translation of provider-specific persistence exceptions into Spring's unified DataAccessException hierarchy.Class@Repository public class OrderRepositoryImpl { }
@ControllerWeb / MVCSpecialization of @Component for MVC controllers that return view names to be resolved and rendered.Class@Controller public class HomeController { }
@RestControllerWeb / MVCMeta-annotation combining @Controller + @ResponseBody — every handler method's return value is serialized straight to the response body.Class@RestController public class TaskController { }
@AutowiredCore / DIMarks a constructor, setter, or field for dependency injection by type. Optional on a class's single constructor since Spring 4.3.Constructor, Field, Setterpublic TaskService(TaskRepository repo) { } // @Autowired optional here
@QualifierCore / DIDisambiguates which bean to inject by name when multiple candidate beans implement the same type.Field, Parameter, Method@Qualifier("primaryDataSource") DataSource ds
@PrimaryCore / DIMarks one bean as the default injection candidate among several beans of the same type.Class, Method (@Bean)@Primary @Bean DataSource primaryDataSource() { }
@ValueCore / DIInjects a literal or a ${property.placeholder} / SpEL expression value into a field or parameter.Field, Parameter@Value("${server.port}") int port
@ConfigurationCore / ConfigMarks a class as a source of bean definitions via @Bean methods; CGLIB-proxied so inter-bean method calls stay singleton-safe.Class@Configuration public class AppConfig { }
@BeanCore / ConfigDeclares a single bean at the method level inside a @Configuration class — used for third-party classes you can't annotate directly.Method@Bean public Clock clock() { return Clock.systemUTC(); }
@ComponentScanCore / ConfigTells Spring which base package(s) to scan for stereotype-annotated classes.Class@ComponentScan("com.example.taskflow")
@ScopeCore / LifecycleSets a bean's scope: singleton (default), prototype, request, session, or application.Class, Method (@Bean)@Scope("prototype") @Component class ReportBuilder { }
@LazyCore / LifecycleDefers a singleton bean's instantiation until it's first requested, instead of eagerly at context startup.Class, Field, Method, Parameter@Lazy @Autowired ReportService reportService;
@PostConstructCore / LifecycleMarks a method to run exactly once, immediately after dependency injection completes and before the bean is put into service.Method@PostConstruct void init() { }
@PreDestroyCore / LifecycleMarks a method to run exactly once, just before a singleton bean is destroyed on container shutdown.Method@PreDestroy void shutdown() { }
@ProfileCore / ConfigRestricts a bean or configuration class to only activate under named environment profiles (e.g. dev, prod).Class, Method@Profile("dev") @Bean DataSource devDataSource() { }
@ImportCore / ConfigExplicitly imports additional @Configuration classes into the application context.Class@Import(SecurityConfig.class)
@PropertySourceCore / ConfigLoads an additional .properties/.yml file's values into the Spring Environment.Class@PropertySource("classpath:extra.properties")
@SpringBootApplicationBoot / MetaMeta-annotation combining @Configuration + @EnableAutoConfiguration + @ComponentScan; goes on the application's entry-point class.Class@SpringBootApplication public class TaskflowApplication { }
@EnableAutoConfigurationBoot / ConfigTurns on Spring Boot's classpath- and bean-driven auto-configuration mechanism.Class@EnableAutoConfiguration public class AppConfig { }
@ConditionalOnPropertyBoot / ConfigApplies a bean or configuration only if a specified property is present and matches an expected value.Class, Method@ConditionalOnProperty(name = "feature.x", havingValue = "true")
@ConditionalOnMissingBeanBoot / ConfigApplies an auto-configured bean only if no bean of that type already exists — the mechanism that lets your own @Bean silently override auto-configuration.Method@Bean @ConditionalOnMissingBean public Clock clock() { }
@ConditionalOnClassBoot / ConfigApplies a configuration only if a specified class is present on the classpath — how Boot detects "is Redis/Kafka/etc. even in use?"Class, Method@ConditionalOnClass(RedisTemplate.class)
@ConfigurationPropertiesBoot / ConfigBinds a whole prefixed block of external configuration onto a strongly-typed POJO or record, instead of many individual @Value injections.Class, Method (@Bean)@ConfigurationProperties(prefix = "app.mail")
@RequestMappingWeb / MVCBase annotation mapping a class or method to a URL path, HTTP method, and/or media type; the method-specific shortcuts below are preferred in practice.Class, Method@RequestMapping("/api/v1/tasks")
@GetMappingWeb / MVCShortcut for @RequestMapping(method = GET) — the idiomatic way to map a read/query endpoint.Method@GetMapping("/{id}")
@PostMappingWeb / MVCShortcut for @RequestMapping(method = POST) — typically a resource-creation endpoint.Method@PostMapping
@PutMappingWeb / MVCShortcut for @RequestMapping(method = PUT) — a full, idempotent resource replacement.Method@PutMapping("/{id}")
@PatchMappingWeb / MVCShortcut for @RequestMapping(method = PATCH) — a partial resource update.Method@PatchMapping("/{id}")
@DeleteMappingWeb / MVCShortcut for @RequestMapping(method = DELETE).Method@DeleteMapping("/{id}")
@PathVariableWeb / BindingBinds a URI template variable (e.g. the {id} in /tasks/{id}) to a method parameter.Parameter@PathVariable Long id
@RequestParamWeb / BindingBinds a query-string or form parameter to a method parameter, with optional default value / required flag.Parameter@RequestParam(defaultValue = "0") int page
@RequestBodyWeb / BindingDeserializes the HTTP request body (typically JSON via Jackson) into a method parameter object — almost always paired with @Valid.Parameter@RequestBody TaskRequest request
@ResponseBodyWeb / BindingWrites a handler method's return value directly to the HTTP response body, bypassing view resolution; implied on every method when the class is @RestController.Method, Class@ResponseBody public TaskResponse get(Long id) { }
@ResponseStatusWeb / ResponseFixes the HTTP status code returned by a handler method or thrown exception class, without needing a ResponseEntity.Method, Class@ResponseStatus(HttpStatus.NOT_FOUND) class TaskNotFoundException { }
@RequestHeaderWeb / BindingBinds an HTTP request header's value to a method parameter.Parameter@RequestHeader("Authorization") String token
@CrossOriginWeb / CORSEnables and configures Cross-Origin Resource Sharing for a controller class or individual handler method.Class, Method@CrossOrigin(origins = "https://app.example.com")
@ExceptionHandlerWeb / ErrorsMarks a method that handles a specific exception type thrown within the same controller, or globally when combined with @RestControllerAdvice.Method@ExceptionHandler(TaskNotFoundException.class)
@RestControllerAdviceWeb / ErrorsApplies @ExceptionHandler methods globally across every controller in the application, returning JSON (typically ProblemDetail for RFC 7807 responses).Class@RestControllerAdvice public class GlobalExceptionHandler { }
@ValidWeb / ValidationTriggers Jakarta Bean Validation on an annotated method parameter (e.g. a @RequestBody DTO) before the handler body runs.Parameter, Fieldcreate(@Valid @RequestBody TaskRequest request)
@ValidatedWeb / ValidationSpring's variant of @Valid; additionally supports validation groups and, on a class, enables method-level parameter validation on plain service beans.Class, Parameter@Validated public class TaskController { }
@NotBlankValidationJakarta Bean Validation constraint: the annotated String must be non-null and contain at least one non-whitespace character.Field, Parameter@NotBlank String title
@NotNullValidationJakarta Bean Validation constraint: the annotated value must not be null (but empty strings/collections are allowed).Field, Parameter@NotNull Instant dueDate
@SizeValidationJakarta Bean Validation constraint: bounds the length of a String, collection, or array between a min and max.Field, Parameter@Size(max = 200) String title
@EntityData / JPAMarks a class as a JPA-managed persistent entity mapped to a database table.Class@Entity @Table(name = "tasks") class Task { }
@TableData / JPACustomizes the table (and optionally schema/catalog) name an entity maps to; without it, JPA defaults to the class name.Class@Table(name = "tasks")
@IdData / JPAMarks a field as the entity's primary key.Field@Id @GeneratedValue Long id;
@GeneratedValueData / JPASpecifies the primary-key generation strategy: IDENTITY, SEQUENCE, TABLE, or AUTO.Field@GeneratedValue(strategy = GenerationType.IDENTITY)
@ColumnData / JPACustomizes column mapping details for a field — name, nullability, length, uniqueness.Field@Column(name = "due_date", nullable = false)
@OneToManyData / JPADeclares a one-to-many association; almost always paired with mappedBy on the non-owning side and FetchType.LAZY.Field@OneToMany(mappedBy = "order") List<OrderLine> lines;
@ManyToOneData / JPADeclares a many-to-one association — the owning side that holds the foreign key.Field@ManyToOne @JoinColumn(name = "order_id") Order order;
@ManyToManyData / JPADeclares a many-to-many association, backed by a join table.Field@ManyToMany List<Role> roles;
@JoinColumnData / JPASpecifies the foreign-key column name for an association, overriding JPA's default naming.Field@JoinColumn(name = "order_id")
@QueryData / RepositoryDefines a custom JPQL (or native SQL, with nativeQuery = true) query directly on a Spring Data repository method.Method@Query("select t from Task t where t.status = :status")
@ModifyingData / RepositoryMarks a @Query method as an UPDATE/DELETE (bulk) operation rather than a SELECT; required or Spring Data throws an exception.Method@Modifying @Query("update Task t set t.status = :s where t.id = :id")
@TransactionalService / TxWraps a method in a database transaction; configurable propagation, isolation level, readOnly flag, and rollback rules. Belongs on the service layer, applied via a Spring proxy — self-invocation within the same class bypasses it.Class, Method@Transactional(readOnly = true) public TaskResponse get(Long id) { }
@EnableWebSecuritySecurity / ConfigActivates Spring Security's web security support, enabling customization of the SecurityFilterChain.Class@EnableWebSecurity public class SecurityConfig { }
@PreAuthorizeSecurity / MethodEvaluates a SpEL authorization expression before a method executes; the most flexible method-security annotation.Method@PreAuthorize("hasRole('ADMIN')")
@PostAuthorizeSecurity / MethodEvaluates a SpEL authorization expression after a method executes, with access to its return value via returnObject.Method@PostAuthorize("returnObject.ownerId == authentication.name")
@SecuredSecurity / MethodRestricts method access to callers holding one of the listed roles — a simpler, non-SpEL alternative to @PreAuthorize.Method@Secured("ROLE_ADMIN")
@AuthenticationPrincipalSecurity / BindingInjects the currently authenticated principal directly into a controller method parameter.Parameter@AuthenticationPrincipal UserDetails user
@AspectAOPMarks a class as containing advice to be woven into matching join points elsewhere in the application.Class@Aspect @Component public class LoggingAspect { }
@AroundAOPDeclares advice that wraps a matched method execution entirely, controlling whether/when/how the original method runs — the most powerful (and most misusable) AOP advice type.Method@Around("execution(* com.example..service.*.*(..))")
@CacheableCachingCaches a method's return value keyed by its arguments; on a cache hit, the method body doesn't execute at all.Method@Cacheable("tasks") public TaskResponse get(Long id) { }
@CacheEvictCachingRemoves one or more entries from a cache, typically applied to a write/update method to keep the cache consistent.Method@CacheEvict(value = "tasks", key = "#id")
@EnableCachingConfig / CachingActivates Spring's annotation-driven caching abstraction (@Cacheable/@CacheEvict/@CachePut).Class@EnableCaching public class CacheConfig { }
@ScheduledSchedulingRuns a method on a fixed schedule — a cron expression, fixed rate, or fixed delay.Method@Scheduled(cron = "0 0 * * * *")
@AsyncAsyncRuns a method on a separate thread pool and returns immediately, optionally returning a Future/CompletableFuture.Method@Async public CompletableFuture<Void> sendEmail() { }
@SpringBootTestTestingBoots the full Spring application context for a broad integration test — the slowest but most realistic test slice.Class@SpringBootTest class TaskApiIntegrationTest { }
@WebMvcTestTestingBoots only the web layer (controllers, filters, @ControllerAdvice) for a fast, focused MVC slice test, with service beans typically mocked.Class@WebMvcTest(TaskController.class)
@DataJpaTestTestingBoots only the JPA layer (repositories, entity manager, an in-memory or Testcontainers-backed database) for a focused persistence slice test.Class@DataJpaTest class TaskRepositoryTest { }
@MockBeanTestingReplaces a real bean in the test's Spring context with a Mockito mock, wired in automatically by type.Field@MockBean TaskService taskService;
@ActiveProfilesTestingActivates one or more named Spring profiles for the duration of a test class (e.g. a dedicated test profile).Class@ActiveProfiles("test")
How to use this table in an interview
Don't try to memorize all 70+ rows — interviewers care far more about whether you can explain why an annotation exists and what problem it solves than whether you can recite its full name. Group them mentally by layer (container/DI, web, data, security, testing) the way this table is scoped, and be ready to go one level deeper on the ones every Spring shop uses daily: @Transactional's propagation/self-invocation gotcha, the difference between @Controller and @RestController, and how @ConditionalOnMissingBean lets your own beans override auto-configuration.
