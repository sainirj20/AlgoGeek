SYSTEM DESIGN

Index

Every system covered in this section, in one alphabetical lookup table — twelve widely-referenced distributed systems and platforms, each broken down into internal architecture, end-to-end request walkthroughs, the underlying math, real-world usage, trade-offs, and interview Q&A. Click any column header to sort — click again to reverse the order.

SystemShort DescriptionCategoryPage Link
Amazon Dynamo Amazon's 2007 highly-available key-value store — consistent hashing with virtual nodes, sloppy quorum, hinted handoff, vector clocks, and gossip-based membership, built so shopping-cart writes are never rejected. A textbook AP system and the direct ancestor of DynamoDB. Key-Value Store (AP) View details →
Apache Bigtable (Google Bigtable) Google's sparse, distributed, persistent multi-dimensional sorted map — a three-level tablet-location hierarchy, memtable/SSTable/commit-log tablet serving, and master-driven tablet splitting/load balancing. The original wide-column design that inspired both HBase and Cassandra. Wide-Column Store (CP) View details →
Apache Cassandra Masterless, peer-to-peer wide-column database combining Bigtable's data model with Dynamo's distribution model — gossip membership with phi-accrual failure detection, an LSM-tree write path, pluggable compaction strategies, and tunable per-request consistency levels. Wide-Column Store (Tunable) View details →
Apache Kafka Distributed, partitioned, append-only log platform for high-throughput event streaming — leader/follower replication with an in-sync-replica set, KRaft-based controller consensus, log compaction, and zero-copy transfer for maximum disk-to-network throughput. Distributed Log / Streaming View details →
Apache ZooKeeper A wait-free coordination service for distributed systems — a hierarchical znode namespace, the ZAB atomic-broadcast protocol for linearizable writes via majority quorum, ephemeral/sequential znodes, and one-shot watches. The canonical CP building block behind distributed locks, leader election, and service discovery. Coordination Service (CP) View details →
BitTorrent A peer-to-peer file-distribution protocol with no central server — pieces verified by hash, rarest-first piece selection, a tit-for-tat choking algorithm for fairness, and a Kademlia DHT for trackerless peer discovery. The definitive example of a purely incentive-driven distributed system. P2P File Distribution View details →
Google Analytics A web/app analytics pipeline collecting billions of client-side events per day — a Lambda-style architecture with a real-time streaming path (HyperLogLog / Count-Min Sketch approximation) and an exact batch path for historical rollups, funnels, and attribution. Analytics Pipeline (Stream + Batch) View details →
Google File System (GFS) Google's single-master distributed file system built for huge, append-heavy files — 64 MB chunks, lease-based mutation ordering, a relaxed "consistent vs. defined" consistency model, and lazy garbage collection. Direct ancestor of HDFS and Google's own Colossus. Distributed File System View details →
Kibana / ELK Observability Stack A unified observability platform bundling distributed tracing, metrics collection, cluster health monitoring, and log aggregation behind one shared ingestion spine and a single Kibana-style dashboard. Built on Elasticsearch's inverted index and Index Lifecycle Management for tiered retention. Observability Platform View details →
Optimizely (A/B Testing) An experimentation platform running hundreds of concurrent experiments — deterministic hash-based bucketing for stateless variation assignment, mutually-exclusive layers to prevent interaction effects, and a sequential-testing statistics engine that avoids the classic "peeking" problem. Experimentation Platform View details →
RabbitMQ (Distributed Message Queue) A general-purpose message broker built on the AMQP model — flexible exchange-based routing (direct/topic/fanout/headers), Raft-replicated quorum queues for durability, and consumer acknowledgment/prefetch for reliable, backpressure-aware delivery. Message Broker (Routing-Centric) View details →
Redis Single-threaded, in-memory data structure store — an event-loop concurrency model, rich data types (strings, lists, hashes, sets, sorted sets, bitmaps, HyperLogLog, streams), RDB/AOF persistence, and Redis Cluster hash-slot sharding with failover. In-Memory Data Structure Store View details →
