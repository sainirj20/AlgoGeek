Tooling & IDE Setup

Overview

This page is the landscape survey for the module — a practical map of the AI tooling ecosystem a Java/Spring backend developer runs into in 2025/2026. Three categories matter for day-to-day work: (a) AI coding assistants that live inside your IDE and speed up the code you write by hand, (b) hosted or self-hosted LLM APIs that your application code calls at runtime to power features, and (c) vector databases you integrate with to support retrieval-augmented generation (RAG). The API and vector-database choices tie directly back to the RAG pipeline covered in Module 1 and the Spring AI / LangChain4j ingestion pipelines from Module 2 — this page is about picking the concrete products that sit behind those abstractions.

AI Coding Assistants in Java IDEs

These tools live where you write code every day. They differ mainly in how deeply they understand your whole codebase versus just the current file, and how much autonomy they're given to make multi-file changes on your behalf.

GitHub Copilot

Copilot is the most widely deployed assistant, with mature plugins for both IntelliJ IDEA and VS Code. Its core experience is inline autocomplete driven by the surrounding file plus open-tab context, and a chat panel for ask-and-answer style help. Copilot Workspace and Copilot's agent mode extend this to multi-file changes — you describe a task, Copilot proposes a plan and a set of file edits across the repo, and you review/apply them. It's sold as a per-seat subscription (individual, Business, Enterprise tiers), which makes it an easy default for teams that already standardize on GitHub.

Cursor / Windsurf

Cursor and Windsurf are AI-native forks of VS Code — the editor itself was rebuilt around AI workflows rather than having AI bolted on as an extension. Their signature feature is an "agent mode" that can plan and execute changes across many files at once, using an index of the whole codebase for context rather than just open tabs. Edits are typically presented as review-and-apply diffs, so you stay in control of what actually lands, while still getting far more autonomy than a single-file autocomplete tool.

Claude Code

Claude Code is different in kind from the other three: it's not an IDE or an IDE plugin at all, but a terminal-based agentic coding tool from Anthropic. It runs as a CLI agent that can read and edit files, run shell commands, execute tests, and carry out multi-step engineering tasks with a good deal of autonomy — closer to a scriptable pair-programmer than an autocomplete widget. Because it operates in the terminal, it works alongside whatever IDE or editor you already use (IntelliJ, VS Code, vim, whatever) instead of replacing it.

JetBrains AI Assistant

JetBrains AI Assistant is native to IntelliJ IDEA (and the rest of the JetBrains family), which lets it lean on JetBrains' own long-standing code understanding and indexing engine rather than a generic language-server view of the project. It offers inline completion, an in-IDE chat panel that understands your project structure, and smaller productivity features like automatic commit-message generation from a diff. For teams already deeply invested in the JetBrains toolchain, it's the lowest-friction option.

Tool IDE Integration Autocomplete Multi-file / Agentic Edits Best For
GitHub Copilot IntelliJ & VS Code plugin Yes, mature Yes — Copilot Workspace / agent mode Teams standardized on GitHub, broad plugin support
Cursor / Windsurf Standalone AI-native VS Code fork Yes Yes — codebase-wide agent mode with apply-diff review Developers wanting the deepest whole-repo AI context
Claude Code None — terminal CLI, works alongside any editor No (not its model) Yes — autonomous multi-step CLI agent Automating engineering tasks: refactors, migrations, scripted changes

Cloud & Hosted AI APIs for Java

These are the LLM providers your Spring Boot services actually call at runtime — the same providers that Spring AI and LangChain4j wrap behind their model abstractions.

OpenAI

OpenAI offers the GPT model family through a REST API with a mature function-calling/tools interface, which made it the reference implementation many frameworks (including Spring AI and LangChain4j) modeled their own tool-calling abstractions on. It has the broadest third-party SDK and ecosystem support of any provider, which matters if you're integrating with existing tooling.

Anthropic Claude

Claude is accessed via the Messages API, with particularly strong support for tool use and multi-step agentic workflows and large context windows for feeding in bigger documents or codebases. Claude Code (covered above) is itself built on top of this API, which is a useful signal for how well the API supports agentic, multi-step tool-calling patterns in production.

Google Gemini

Gemini is available either through Vertex AI (Google Cloud's managed ML platform) or directly via the Gemini API. It has strong multimodal support (text, image, audio, video in a single model) and the tightest integration if your infrastructure already lives on GCP — IAM, billing, and networking all fall under the same umbrella.

Ollama

Ollama lets you run open-weight models — Llama, Mistral, Gemma, and others — locally on your own machine or server. There's zero per-token cost and full data privacy, since nothing leaves your infrastructure, which makes it attractive for regulated data or simply for iterating without burning API credits. The trade-off is that you own the hardware and inference performance problem yourself: model quality and latency are bounded by whatever GPU/CPU you can throw at it.

Provider Hosting Model Cost Model Data Privacy Typical Java Integration
OpenAI Fully hosted (OpenAI cloud) Per-token, tiered by model Data sent to OpenAI's servers Spring AI / LangChain4j OpenAI starter, or raw REST client
Anthropic Claude Fully hosted (Anthropic cloud) Per-token, tiered by model Data sent to Anthropic's servers Spring AI / LangChain4j Anthropic starter, or Messages API client

Ollama Self-hosted, local or on your own server Zero per-token cost (you pay for hardware) Nothing leaves your infrastructure Local REST API — first-class support in both Spring AI and LangChain4j

Java Vector Database Integrations

Once your RAG pipeline has embeddings, they need to live somewhere that supports fast similarity search. The right choice usually comes down to how much new infrastructure you're willing to operate.

Milvus

Milvus is a purpose-built, horizontally scalable vector database designed for very large embedding collections. It gives you strong performance at scale, but it's its own deployment — you stand up and operate a Milvus cluster (or use a managed offering) rather than reusing infrastructure you already run.

pgvector

pgvector is a Postgres extension, not a separate database. If you already run Postgres, you add a vector column type and similarity-search operators directly inside your existing database — no new infrastructure, no new operational surface, and your embeddings live right next to your relational data in the same transactions.

Qdrant

Qdrant is a purpose-built vector database written in Rust, exposing a simple REST and gRPC API. It's popular specifically for its developer experience — straightforward setup, clear API semantics, and good client libraries — making it a common choice when you want a dedicated vector store without Milvus-level operational complexity.

Vector DB Deployment Model Indexing Algorithm Java Client When To Choose It
Milvus Own cluster (self-managed or managed service), horizontally scalable HNSW, IVF, and others (configurable) Official Java SDK Very large-scale embedding collections, dedicated vector workloads
pgvector Extension inside an existing Postgres instance HNSW or IVFFlat Standard JDBC driver — no separate client needed You already run Postgres and want to avoid new infrastructure
Qdrant Standalone service (self-hosted or managed cloud) HNSW Official Java client over REST/gRPC Dedicated vector store with a simple, developer-friendly API

Because pgvector is just Postgres, the query shape is the one most Java developers will recognize fastest — a normal table with a vector column, and a similarity search using a distance operator: 

CREATE TABLE document_chunks (
    id BIGSERIAL PRIMARY KEY,
    content TEXT NOT NULL,
    embedding VECTOR(1536)
);

-- Find the 5 chunks most similar to a query embedding
-- using cosine distance (<=>); <-> is Euclidean (L2) distance
SELECT id, content
FROM document_chunks
ORDER BY embedding <=> '[0.012, -0.034, 0.101, ...]'
LIMIT 5;

Practical Setup Tips

Setting up a sane day-to-day workflow
  • Use Ollama locally during development so you can iterate freely without burning API credits on a hosted provider — switch to a hosted model (OpenAI, Claude, Gemini) once you need production-grade quality or scale.
  • Keep API keys out of source control entirely — load them from environment variables or a secrets manager, never hardcode them in application properties or commit them to git.
  • Treat AI-assistant-generated code exactly like a junior engineer's pull request: review it line by line, run the tests, and don't merge blind just because it compiles and looks plausible.
  • Match the assistant to the task — inline autocomplete tools are great for boilerplate, while agentic tools (Copilot agent mode, Cursor/Windsurf agent mode, Claude Code) are better suited to larger, well-scoped multi-file changes you can review as a diff.

Key Takeaways

  • Three tool categories matter for a Java developer: IDE coding assistants, hosted/local LLM APIs, and vector databases for RAG.
  • IDE assistants range from autocomplete-first (Copilot, JetBrains AI Assistant) to fully agentic, codebase-wide editors (Cursor, Windsurf) to a terminal-native agent that isn't an IDE at all (Claude Code).
  • Hosted LLM APIs (OpenAI, Anthropic Claude, Google Gemini) trade cost and data-leaves-your-network for top-tier model quality; Ollama flips that trade-off by running open-weight models locally for free with full data privacy.
  • Vector database choice mostly comes down to infrastructure reuse: pgvector if you already run Postgres, Qdrant for a simple dedicated vector store, Milvus for very large-scale, horizontally scalable workloads.
  • Both Spring AI and LangChain4j have first-class support for Ollama's local REST API, making local development a drop-in replacement for a hosted provider during the build phase.
  • Always review AI-generated code like you would a junior engineer's PR, and never commit API keys to source control.
