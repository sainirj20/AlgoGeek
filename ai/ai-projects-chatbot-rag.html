AI Projects: Chatbot & RAG

Overview

Reading about LLMs, RAG, and Skills builds vocabulary for an interview, but nothing cements the concepts like building two small, real, working things. This page walks through two beginner-friendly projects end to end: a custom command-line chatbot with real conversation memory, and a simple Retrieval-Augmented Generation pipeline over your own text documents — both using the Anthropic API directly, with no framework required. Each project is intentionally kept small enough to build in an afternoon, with notes on how to grow it toward a production-grade version afterward.

Before you start
Both projects need an Anthropic API key (create one at platform.claude.com) and the official Python SDK: pip install anthropic. Never hard-code an API key into source you might commit or share — load it from an environment variable, as shown below. Model names shown (e.g. claude-sonnet-5) are illustrative; always check current model names in the Claude API docs, since the available model lineup changes over time.

Project 1 — Build a Custom Chatbot

The goal is a small command-line chatbot that remembers the conversation so far, follows a persona you define, and streams its reply token-by-token instead of making you wait for the whole answer.

Step 1 — The simplest possible call

Every Claude API call is a request containing a model name, a token budget, and a list of messages. Start here to confirm your setup works before adding anything else:

import os
import anthropic

client = anthropic.Anthropic(api_key=os.environ["ANTHROPIC_API_KEY"])

response = client.messages.create(
    model="claude-sonnet-5",
    max_tokens=512,
    messages=[
        {"role": "user", "content": "Say hello in one short sentence."}
    ],
)

print(response.content[0].text)

Step 2 — Give it a persona with a system prompt

The system parameter sets behavior that applies across the whole conversation — tone, role, constraints — separately from the back-and-forth messages list:

SYSTEM_PROMPT = (
    "You are Ada, a friendly and concise coding mentor. "
    "Explain things simply, use short examples, and never ramble."
)

response = client.messages.create(
    model="claude-sonnet-5",
    max_tokens=512,
    system=SYSTEM_PROMPT,
    messages=[
        {"role": "user", "content": "What's a closure in JavaScript?"}
    ],
)
print(response.content[0].text)

Step 3 — Add real conversation memory

The API itself is stateless — it has no memory of previous calls. A chatbot "remembers" only because you resend the full message history (including the model's own previous replies) on every call. This is the single most important idea in building any conversational app on top of the API:

history = []

def ask(user_text: str) -> str:
    history.append({"role": "user", "content": user_text})
    response = client.messages.create(
        model="claude-sonnet-5",
        max_tokens=512,
        system=SYSTEM_PROMPT,
        messages=history,
    )
    reply = response.content[0].text
    history.append({"role": "assistant", "content": reply})
    return reply

print(ask("My name is Priya."))
print(ask("What's my name?"))   # Works, because history[] carries it forward

Step 4 — Stream the response

For a chat-like feel, stream tokens as they're generated instead of blocking until the full reply is ready:

def ask_streaming(user_text: str) -> str:
    history.append({"role": "user", "content": user_text})
    full_reply = ""
    with client.messages.stream(
        model="claude-sonnet-5",
        max_tokens=512,
        system=SYSTEM_PROMPT,
        messages=history,
    ) as stream:
        for text in stream.text_stream:
            print(text, end="", flush=True)
            full_reply += text
    print()
    history.append({"role": "assistant", "content": full_reply})
    return full_reply

Step 5 — Put it together as a CLI loop

import os
import anthropic

client = anthropic.Anthropic(api_key=os.environ["ANTHROPIC_API_KEY"])
SYSTEM_PROMPT = (
    "You are Ada, a friendly and concise coding mentor. "
    "Explain things simply, use short examples, and never ramble."
)
history = []

def ask_streaming(user_text: str) -> str:
    history.append({"role": "user", "content": user_text})
    full_reply = ""
    with client.messages.stream(
        model="claude-sonnet-5",
        max_tokens=512,
        system=SYSTEM_PROMPT,
        messages=history,
    ) as stream:
        for text in stream.text_stream:
            print(text, end="", flush=True)
            full_reply += text
    print()
    history.append({"role": "assistant", "content": full_reply})
    return full_reply

if __name__ == "__main__":
    print("Ada is ready. Type 'quit' to exit.\n")
    while True:
        user_text = input("You: ")
        if user_text.strip().lower() == "quit":
            break
        print("Ada: ", end="")
        ask_streaming(user_text)
Where to take it next
Trim history once it approaches the model's context window (drop or summarize the oldest turns), persist it to a file or database so the chatbot survives a restart, and add tool use if you want Ada to actually do things (look up data, call an API) rather than just talk — that's the same tool-calling mechanism that powers the AI coding agents and MCP integrations covered elsewhere in this section.

Project 2 — Build a Simple RAG Pipeline

The goal is a small script that answers questions about a folder of your own text files, grounded in their actual content — the same core idea covered conceptually on the AI System Design page, built here as real, runnable code with no vector database required.

Step 1 — Chunk your documents

Split each document into overlapping passages so no single chunk gets too large to embed meaningfully, and so a fact near a chunk boundary isn't lost entirely:

def chunk_text(text: str, chunk_size: int = 800, overlap: int = 100) -> list[str]:
    chunks = []
    start = 0
    while start < len(text):
        end = start + chunk_size
        chunks.append(text[start:end])
        start += chunk_size - overlap
    return chunks

# Load and chunk every .txt file in a folder
import glob

all_chunks = []          # list of {"text": ..., "source": ...}
for path in glob.glob("docs/*.txt"):
    with open(path, encoding="utf-8") as f:
        text = f.read()
    for chunk in chunk_text(text):
        all_chunks.append({"text": chunk, "source": path})

Step 2 — Embed every chunk

Anthropic's own RAG cookbook recommends Voyage AI's embedding models for retrieval quality. Install with pip install voyageai:

import voyageai

vo = voyageai.Client(api_key=os.environ["VOYAGE_API_KEY"])

texts = [c["text"] for c in all_chunks]
embeddings = vo.embed(texts, model="voyage-3", input_type="document").embeddings

for chunk, embedding in zip(all_chunks, embeddings):
    chunk["embedding"] = embedding

Step 3 — Retrieve by cosine similarity

No vector database is needed at small scale — a plain in-memory cosine-similarity scan over a few hundred or few thousand chunks is fast enough, and it makes the mechanics fully visible:

import numpy as np

def cosine_similarity(a, b) -> float:
    a, b = np.array(a), np.array(b)
    return float(np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b)))

def retrieve(query: str, k: int = 4) -> list[dict]:
    query_embedding = vo.embed([query], model="voyage-3", input_type="query").embeddings[0]
    scored = [
        (cosine_similarity(query_embedding, c["embedding"]), c)
        for c in all_chunks
    ]
    scored.sort(key=lambda pair: pair[0], reverse=True)
    return [chunk for _, chunk in scored[:k]]

Step 4 — Generate a grounded answer

Feed the retrieved chunks into the prompt as context, and explicitly instruct the model to answer only from that context — this is the single highest-leverage line for reducing hallucination in a RAG system:

RAG_SYSTEM_PROMPT = (
    "Answer the user's question using ONLY the context provided below. "
    "If the answer isn't in the context, say you don't know — "
    "do not use outside knowledge."
)

def answer(question: str) -> str:
    top_chunks = retrieve(question)
    context = "\n\n---\n\n".join(
        f"[Source: {c['source']}]\n{c['text']}" for c in top_chunks
    )
    response = client.messages.create(
        model="claude-sonnet-5",
        max_tokens=512,
        system=RAG_SYSTEM_PROMPT,
        messages=[
            {"role": "user", "content": f"Context:\n{context}\n\nQuestion: {question}"}
        ],
    )
    return response.content[0].text

print(answer("What is our policy on refunds after 30 days?"))
Where to take it next
Swap the in-memory scan for a real vector database (Chroma, Pinecone, or similar) once your corpus grows past a few thousand chunks, add a re-ranking pass over the top-k candidates for better precision, try contextual embeddings (prepending a short auto-generated summary of the source document to each chunk before embedding it) to improve retrieval on chunks that lose context in isolation, and add citations in the final answer so users can verify which source backed each claim. See the AI System Design page for the fuller production-grade version of this pipeline, and its Agentic RAG section for how to let the model decide when to re-query instead of retrieving only once.

Common Interview Questions

Your chatbot's history list keeps growing every turn. What breaks eventually, and how would you fix it?
Eventually the accumulated messages exceed the model's context window, and the request fails or the model loses access to the earliest turns. Fixes include trimming to the most recent N turns, summarizing older turns into a compact recap message, or persisting the full history externally while sending only a windowed/summarized version to the API on each call.
Why embed the query with input_type="query" but documents with input_type="document"?
Retrieval-optimized embedding models like Voyage's are trained asymmetrically — queries and documents have systematically different structure (a short question vs. a long passage), so the model applies a different internal transformation depending on which role text is playing. Using the matching input type for each side of the comparison materially improves retrieval quality versus embedding both the same way.
This RAG pipeline scans every chunk's embedding in a Python loop. Why is that acceptable here, and when would it stop being acceptable?
A linear cosine-similarity scan is O(n) per query, which is fast enough at a few hundred to low thousands of chunks — the cost is dwarfed by the LLM generation call itself. It stops being acceptable once the corpus grows large enough that the scan itself adds noticeable latency (tens of thousands of chunks and up) or needs to run at high query volume, at which point an approximate nearest neighbor index (HNSW, IVF) in a real vector database becomes worth the added infrastructure.
The RAG system prompt says "answer only from the provided context." Is that enough to fully prevent hallucination?
It substantially reduces hallucination but doesn't fully eliminate it — the model can still misread or over-extrapolate from the retrieved context, and if retrieval itself fails to surface the relevant chunk, the instruction only guarantees the model says "I don't know" rather than guaranteeing it always finds the right answer. Retrieval quality (chunking, embedding choice, re-ranking) is just as important to hallucination reduction as the prompt-level instruction.
How would you evaluate whether this RAG pipeline actually works well before shipping it?
Build a small labeled set of realistic questions with known correct source chunks, and measure retrieval quality (recall@k — does the right chunk show up in the top k?) separately from generation quality (does the final answer correctly and faithfully use what was retrieved?). Spot-check a sample of real answers by hand before fully trusting an automated or LLM-as-judge score, since early-stage evaluation sets are usually too small to fully trust in isolation.

Key Takeaways

Remember
A chatbot's "memory" is nothing more than you resending the full message history on every stateless API call — there's no hidden server-side memory. A minimal RAG pipeline is just four steps in code: chunk, embed, retrieve by cosine similarity, and generate with the retrieved context injected into the prompt and an explicit "answer only from context" instruction. Both projects are intentionally small enough to build without a framework, which is exactly what makes the underlying mechanics — and their failure modes — visible.
