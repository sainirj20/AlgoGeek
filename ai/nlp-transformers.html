NLP & Transformers

Overview

The transformer architecture, introduced in "Attention Is All You Need" (2017), underpins essentially every modern language model. Interviewers probe this topic to see whether you understand how raw text becomes numeric input, how self-attention actually computes relationships between tokens, and how the three transformer variants (encoder-only, decoder-only, encoder-decoder) map to different tasks.

Tokenization

SchemeUnitTrade-off
Word-levelWhole wordsIntuitive, but huge vocabulary and no handling of unseen/rare words (OOV problem)
Character-levelIndividual charactersTiny vocabulary, no OOV issue, but very long sequences and weaker semantic grouping
Subword (BPE / WordPiece / SentencePiece)Frequent character n-grams merged iterativelyBalances vocabulary size and sequence length; handles rare words by splitting into known subword pieces

Byte-Pair Encoding (BPE) starts with individual characters and iteratively merges the most frequent adjacent pair into a new token, repeating until a target vocabulary size is reached. This means common words stay as a single token while rare or unseen words decompose into smaller, still-meaningful subword pieces (e.g. "tokenization" → "token" + "ization") — nearly every modern LLM uses some variant of this approach.

Embeddings

An embedding maps a discrete token to a dense vector in continuous space, learned so that semantically similar tokens end up close together (by cosine similarity or dot product). Early static embeddings (Word2Vec, GloVe) assigned one fixed vector per word regardless of context. Transformer-based contextual embeddings instead produce a different vector for the same word depending on its surrounding context (e.g. "bank" of a river vs. a "bank" account get different representations), which is a major reason transformer models outperform earlier bag-of-embeddings approaches.

The Transformer Architecture

A transformer block processes an entire sequence at once rather than one token at a time. The two central ideas are self-attention, which lets each token look at every other token and weigh how relevant each one is, and positional encoding, which injects information about token order since attention itself has no inherent notion of sequence position.

Scaled Dot-Product Attention

Each token is projected into three vectors: a Query (what this token is looking for), a Key (what this token offers), and a Value (the content it contributes if attended to). Attention weights come from comparing every Query against every Key, then those weights are used to combine the Values.

Scaled dot-product attention Attention(Q, K, V) = softmax( QKT / √dk ) V
Q, K, V are learned linear projections of the input; dk is the key dimension. Dividing by √dk prevents dot products from growing too large and pushing softmax into regions with vanishing gradients.

Multi-Head Attention

Rather than computing a single attention function, the model runs several attention "heads" in parallel, each with its own learned Q/K/V projections, then concatenates and linearly projects the results. Each head can specialize in a different type of relationship (e.g. one head tracks syntactic dependency, another tracks coreference), giving the model a richer combined representation than a single attention computation could.

Positional Encoding

Because self-attention treats the input as an unordered set of vectors, the model needs an explicit signal for token order. The original transformer adds fixed sinusoidal positional encodings to each token embedding; many modern models instead use learned positional embeddings or relative encodings like RoPE (rotary positional embeddings), which generalize better to sequence lengths not seen during training.

def scaled_dot_product_attention(Q, K, V, mask=None):
    d_k = Q.shape[-1]
    scores = Q @ K.transpose(-2, -1) / math.sqrt(d_k)
    if mask is not None:
        scores = scores.masked_fill(mask == 0, float('-inf'))
    weights = softmax(scores, dim=-1)
    return weights @ V

Encoder-Only vs. Decoder-Only vs. Encoder-Decoder

VariantAttention patternExample modelsBest suited for
Encoder-onlyBidirectional — each token attends to the full sequence, before and afterBERT, RoBERTaClassification, embeddings, extractive QA — tasks needing full-context understanding, not generation
Decoder-onlyCausal/masked — each token attends only to previous tokensGPT family, LLaMAOpen-ended text generation, chat, few-shot in-context learning
Encoder-decoderEncoder is bidirectional; decoder is causal and cross-attends to encoder outputT5, original Transformer, BARTSequence-to-sequence tasks: translation, summarization
Why BERT can't generate text one token at a time
BERT's bidirectional attention means every position sees the full sentence during training — there's no notion of "predict the next token given only what came before." That's exactly what decoder-only models are built for via causal (masked) self-attention, which is why GPT-style models are the default choice for open-ended generation.

Common Interview Questions

Why does scaled dot-product attention divide by √dk?
As the dimension dk grows, the dot products between Q and K tend to grow large in magnitude, pushing the softmax function into regions where its gradient is extremely small (saturation), which slows or stalls learning. Scaling by √dk keeps the dot products in a reasonable range so softmax stays well-behaved.
What's the practical benefit of multi-head attention over a single attention computation?
Each head can learn to attend to different types of relationships (e.g. local syntax vs. long-range coreference) within its own lower-dimensional subspace, and concatenating multiple heads gives the model a richer, multi-faceted representation than one larger single-head attention could easily learn.
Why do transformers need positional encoding at all?
Self-attention is permutation-invariant — it computes a weighted sum over all tokens regardless of order, so without extra information, "the cat sat on the mat" and "the mat sat on the cat" would look identical to the attention mechanism. Positional encodings inject order information into the token representations before they enter the attention layers.
Would you use BERT or GPT for a sentiment classification task, and why?
BERT (encoder-only) is generally preferred for classification: its bidirectional attention lets it build a full-context representation of the input before making a single prediction, and it's typically smaller and cheaper to fine-tune for this kind of task than an autoregressive decoder-only model.
What's the difference between BPE and word-level tokenization in how they handle a rare word like "antidisestablishmentarianism"?
Word-level tokenization would either have this as one rare vocabulary entry (wasting capacity) or mark it as out-of-vocabulary/unknown. BPE instead decomposes it into a sequence of known subword pieces the model has seen before, so it can still represent and generate the word meaningfully without ever having needed it as a single vocabulary entry.

Key Takeaways

Remember
Subword tokenization (BPE) balances vocabulary size against sequence length and OOV handling. Self-attention computes weighted relationships between all token pairs via Q/K/V projections, scaled to keep softmax well-behaved. Multi-head attention lets the model capture multiple relationship types at once. Choose encoder-only for understanding tasks, decoder-only for generation, and encoder-decoder for sequence-to-sequence transformation.
