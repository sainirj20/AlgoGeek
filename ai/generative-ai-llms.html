Generative AI & LLMs

Overview

Large language models are decoder-only transformers trained at massive scale, then adapted through several further stages before they behave like a helpful assistant. This topic covers the training pipeline, the levers you can pull at inference time (prompting, sampling), and why LLMs sometimes confidently produce wrong information.

How LLMs Are Trained

StageObjectiveDataResult
PretrainingNext-token prediction (self-supervised)Massive web-scale text corporaA "base model" with broad language and world knowledge, but no instruction-following behavior
Supervised fine-tuning (SFT)Imitate high-quality human-written responsesCurated (instruction, response) pairsA model that follows instructions in a helpful format
Preference alignment (RLHF / DPO)Prefer responses humans rate as betterHuman (or AI) preference comparisons between candidate responsesA model tuned toward helpful, harmless, honest outputs

RLHF (Reinforcement Learning from Human Feedback) trains a separate reward model on human preference comparisons, then uses reinforcement learning (typically PPO) to fine-tune the LLM to maximize that reward. DPO (Direct Preference Optimization) achieves a similar alignment effect without a separate reward model or RL loop — it directly optimizes the policy on preference pairs using a closed-form loss derived from the same underlying objective, making it simpler and more stable to train.

Prompting Techniques

  • Zero-shot prompting — asking the model to perform a task with no examples, relying entirely on what it learned during training/alignment.
  • Few-shot prompting — including a handful of input/output examples directly in the prompt so the model can infer the desired pattern or format without any weight updates (in-context learning).
  • Chain-of-thought (CoT) prompting — asking the model to reason step by step before giving a final answer, which measurably improves performance on multi-step reasoning and arithmetic tasks by giving the model "space" to work through intermediate steps rather than jumping straight to an answer.
Zero-shot:
"Classify the sentiment of this review: 'The battery life is terrible.'"

Few-shot:
"Review: 'Great sound quality.' -> Positive
 Review: 'Screen cracked on day one.' -> Negative
 Review: 'The battery life is terrible.' -> ?"

Chain-of-thought:
"A store has 23 apples. They sell 15 and receive a shipment of 8.
 Let's think step by step, then give the final count."

Claude Prompting: How to Ask Well

A Skill is a reusable instruction set you write once; a prompt is what you type for one conversation, right now. Getting good at prompting is still worth deliberate practice even once you're relying on Skills and agents for repeated tasks, because prompting is the layer underneath everything else — a well-written Skill or agent is, underneath, still built out of well-written prompts.

Core Principles

  • Be clear and direct. State the goal, the constraints, and the format you want, rather than hinting at them.
  • Give context. Explain why you want something, not just what — output quality improves noticeably when the model understands the goal behind the ask, not only the literal instruction.
  • Use examples (few-shot). Showing one or two examples of the input/output pattern you want is often more effective than describing the pattern in words alone.
  • Structure with tags. Wrapping distinct pieces of a long or complex prompt in tags like <context>, <task>, <examples> helps the model parse which part is which.
  • Ask for step-by-step reasoning on hard problems. Explicitly inviting the model to think through a problem before answering measurably improves accuracy on anything non-trivial — the same underlying effect as chain-of-thought prompting above.
  • Specify the output format precisely. "Answer in 3 bullet points" or "return only valid JSON" removes ambiguity that otherwise gets guessed at.
  • Iterate. Treat the first response as a draft; tell the model specifically what to change rather than starting the whole prompt over.

Prompting an Agent vs. Prompting for a One-Shot Answer

A one-shot prompt asks for an answer. An agent prompt asks for a goal to be achieved, potentially over many tool calls — so it benefits from stating success criteria ("the tests must pass"), constraints ("don't touch files outside src/"), and how much autonomy to take ("ask before deleting anything"). System prompts (or a plugin's default agent configuration) set the standing behavior; the per-message prompt sets the specific task on top of that. See the AI Coding Agents page for what this looks like in a real agentic coding loop.

Prompt injection: a practical risk
Prompt injection is when untrusted content the model reads — a webpage, a document, a tool's output — contains instructions designed to hijack the model's behavior, distinct from the user's actual request. This becomes a real production concern the moment a model reads content it didn't author (browsing, RAG context, tool results) rather than only the user's direct input. Defenses include treating retrieved or tool content strictly as data rather than as instructions, scoping which tools an agent is allowed to call and requiring confirmation for risky actions, and being cautious about installing Skills or MCP connectors from unverified sources, since they can execute code or call tools on the model's behalf.

Hallucination

Hallucination is when a model generates fluent, confident-sounding text that is factually incorrect or unsupported by any real source. It happens because LLMs are trained to predict plausible continuations of text, not to verify truth — the training objective rewards fluency and pattern-consistency, not factual grounding. Contributing factors include gaps or contradictions in training data, the model being pushed outside its knowledge (e.g. asked about very recent events or narrow specialist facts), and decoding strategies that favor fluency over faithfulness. Mitigations include retrieval-augmented generation (grounding answers in retrieved documents), lower temperature for factual tasks, explicit citation requirements, and fine-tuning/RLHF that penalizes unsupported claims.

Sampling: Temperature & Top-p

At each generation step, the model outputs a probability distribution over the vocabulary; a decoding strategy decides which token to actually emit.

  • Temperature rescales the logits before softmax: temperature < 1 sharpens the distribution (more deterministic, favors high-probability tokens), temperature > 1 flattens it (more random/creative), and temperature → 0 approaches greedy decoding (always pick the top token).
  • Top-p (nucleus) sampling restricts sampling to the smallest set of tokens whose cumulative probability exceeds p, then samples only within that set — this adapts the candidate pool size dynamically (few candidates when the model is confident, more when it's uncertain), unlike top-k which always keeps a fixed number of candidates.
Practical guidance
Use low temperature (e.g. 0–0.3) and/or greedy decoding for factual, deterministic tasks like code generation or data extraction. Use higher temperature (e.g. 0.7–1.0) with top-p sampling for creative or open-ended writing where diverse, varied output is desirable.

Context Window Limits

The context window is the maximum number of tokens (prompt plus generated output) a model can attend to at once. Everything beyond that limit is either truncated or must be summarized/retrieved externally. Long context windows are expensive: self-attention's compute and memory cost scales quadratically with sequence length in the naive implementation, though techniques like sparse attention, sliding-window attention, and optimized attention kernels (e.g. FlashAttention) push practical context lengths much higher. Even within the technical limit, models often show a "lost in the middle" effect — better recall of information near the start or end of a long context than in the middle — which matters when designing prompts that stuff in large amounts of retrieved context.

Worked example — request cost estimate cost_per_request = (input_tokens + output_tokens) / 1000 × price_per_1k
e.g. a RAG prompt with 3,000 input tokens + 500 output tokens at $0.01/1K in, $0.03/1K out ≈ $0.045/request
At 100,000 requests/day → ≈ $4,500/day (≈ $1.6M/year) — this is why prompt/context size directly drives production LLM cost.

Common Interview Questions

What's the difference between RLHF and DPO?
RLHF trains a separate reward model on human preference data, then uses reinforcement learning (typically PPO) to optimize the LLM against that reward model — a two-stage, RL-based process that can be unstable and compute-heavy. DPO skips the separate reward model and RL loop entirely, directly optimizing the policy on preference pairs with a supervised-style loss that's mathematically equivalent in objective but much simpler and more stable to train.
Why does chain-of-thought prompting improve performance on math and reasoning tasks?
It gives the model intermediate computation steps to condition on before producing a final answer, rather than forcing it to map the problem directly to an answer in one shot. This mirrors how allocating more "thinking" tokens lets the model break a hard problem into simpler sub-steps it's individually good at.
Why can't you just fine-tune away hallucination entirely?
Hallucination stems from the fundamental nature of next-token prediction — the model has no built-in mechanism to verify claims against ground truth, only to produce statistically plausible text. Fine-tuning and RLHF can reduce hallucination rates (e.g. by penalizing unsupported claims or rewarding "I don't know" responses) but can't eliminate it, since the model still has no real-time access to verified facts; grounding via retrieval remains the most reliable mitigation.
If you wanted deterministic, reproducible output from an LLM, what sampling settings would you use?
Set temperature to 0 (or use greedy/argmax decoding) so the model always picks the highest-probability token at each step, removing randomness from sampling. Note that even at temperature 0, some inference stacks (e.g. due to batching or floating-point non-determinism) may not be perfectly reproducible.
What's the practical difference between top-k and top-p sampling?
Top-k always samples from a fixed number of the most likely next tokens, regardless of how confident the model is. Top-p (nucleus) sampling instead picks the smallest set of tokens whose cumulative probability crosses a threshold p, so the candidate pool shrinks when the model is very confident and grows when it's uncertain — generally producing more natural output than a fixed top-k cutoff.

Key Takeaways

Remember
LLMs go through pretraining (raw capability), SFT (instruction-following format), and preference alignment via RLHF or DPO (helpfulness/safety). Prompting techniques like few-shot and chain-of-thought steer behavior without any weight updates. Good prompting — clarity, context, examples, tagged structure, explicit reasoning requests, precise output format — is the foundation underneath Skills and agents, not a separate beginner skill you graduate past. Treat untrusted content a model reads as data, never as instructions, to defend against prompt injection. Hallucination is inherent to next-token prediction and is best mitigated with grounding (RAG), not just fine-tuning. Temperature and top-p control the creativity/determinism trade-off at inference time.
