Machine Learning Fundamentals

Overview

Before diving into deep learning or LLMs, interviewers check whether you have a solid grip on the fundamentals: the major learning paradigms, why models generalize (or fail to), and how to measure whether a model is actually good. These fundamentals underpin every applied ML system design question that follows.

Supervised vs. Unsupervised vs. Reinforcement Learning

ParadigmSignalGoalExamples
SupervisedLabeled input/output pairsLearn a mapping f(x) → yClassification, regression
UnsupervisedUnlabeled dataDiscover structure in xClustering, dimensionality reduction, density estimation
ReinforcementReward signal from an environmentLearn a policy that maximizes cumulative rewardGame playing, robotics, RLHF for LLMs

Semi-supervised learning (a small labeled set plus a large unlabeled set) and self-supervised learning (labels are derived from the data itself, e.g. predicting a masked word) sit between these categories and are the backbone of how modern foundation models are pretrained.

Bias-Variance Tradeoff

Bias is the error from overly simplistic assumptions in the model — a high-bias model underfits, missing real patterns in the data. Variance is the error from sensitivity to the specific training set — a high-variance model overfits, memorizing noise instead of signal. Total expected error decomposes into three additive terms, and the two you control by choosing model complexity trade off against each other: reducing bias (a more flexible model) tends to increase variance, and vice versa.

Bias-variance decomposition E[(y - &fcirc;(x))²] = Bias[&fcirc;(x)]² + Var[&fcirc;(x)] + σ²
where σ² is irreducible noise. Simple models → high bias, low variance. Complex models → low bias, high variance.

Overfitting, Underfitting & Regularization

Underfitting shows up as high error on both training and validation sets — the model isn't complex enough or wasn't trained long enough. Overfitting shows up as low training error but much higher validation error — the model has fit noise or idiosyncrasies specific to the training set. Common fixes for overfitting: more training data, simpler models, early stopping, dropout (for neural nets), and regularization.

  • L1 (Lasso) — adds λ∑|wi| to the loss. Drives some weights exactly to zero, producing sparse models and acting as implicit feature selection.
  • L2 (Ridge) — adds λ∑wi² to the loss. Shrinks weights smoothly toward zero without eliminating them; tends to handle correlated features better than L1.
  • Elastic Net — a weighted combination of L1 and L2 penalties, useful when you want sparsity but also stability with correlated features.

Train / Validation / Test Splits & Cross-Validation

The training set fits model parameters, the validation set tunes hyperparameters and gives an unbiased read on model choice during development, and the test set — touched exactly once, at the end — estimates real-world generalization. Leaking test data into training or hyperparameter tuning (directly or via repeated peeking) inflates your reported performance and is one of the most common practical mistakes.

k-fold cross-validation splits the training data into k folds, trains on k−1 of them and validates on the remaining fold, rotating through all k combinations and averaging the results. This gives a more robust performance estimate than a single train/validation split, especially with limited data, at the cost of k× the training time. Stratified k-fold preserves class proportions in each fold, which matters for imbalanced classification problems.

Accuracy trap
On an imbalanced dataset (e.g. 1% fraud rate), a classifier that always predicts "not fraud" scores 99% accuracy but is useless. Prefer precision, recall, F1, or ROC-AUC (or PR-AUC for very skewed classes) over raw accuracy whenever classes are imbalanced.

Common Interview Questions

Your model has 98% training accuracy but 70% validation accuracy. What's going on and how do you fix it?
This is a classic overfitting signature — the model has learned patterns (including noise) specific to the training set that don't generalize. Fixes include: adding regularization (L1/L2, dropout), collecting more training data, reducing model complexity, using early stopping based on validation loss, and applying data augmentation where applicable.
Why would you use F1 score instead of accuracy?
F1 balances precision and recall into a single number, which matters when class distribution is imbalanced or when both false positives and false negatives carry real cost. Accuracy alone can look excellent on an imbalanced dataset while the model is practically useless for the minority class.
Explain the difference between L1 and L2 regularization in terms of the resulting weight vector.
L1 (Lasso) tends to push some weights to exactly zero, producing a sparse solution useful for feature selection. L2 (Ridge) shrinks all weights toward zero smoothly but rarely to exactly zero, distributing the penalty more evenly — often preferable when features are correlated since L1 can arbitrarily pick one of a correlated group.
Why use k-fold cross-validation instead of a single train/validation split?
A single split gives one noisy estimate of generalization performance that depends heavily on which examples land in the validation set. k-fold CV averages performance over k different splits, giving a lower-variance estimate and making better use of limited data, at the cost of training the model k times.
When would you pick a high-bias model over a high-variance one?
When training data is scarce or very noisy, a high-variance (complex) model will overfit quickly; a simpler, high-bias model generalizes more reliably. Conversely, with abundant clean data, a more flexible model can afford lower bias without paying an unacceptable variance penalty — this is the core reasoning behind choosing model complexity relative to dataset size.

Key Takeaways

Remember
Match the learning paradigm to the problem (labeled data → supervised, no labels → unsupervised, sequential decisions with rewards → RL). Manage the bias-variance tradeoff with model complexity and regularization. Never let the test set influence training or tuning decisions. Choose evaluation metrics that reflect the real cost of errors, not just raw accuracy.
