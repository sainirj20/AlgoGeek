CLOUD ARCHITECTURE

GCP vs. AWS vs. Azure — Service Comparison

A side-by-side lookup table mapping the same 36 building blocks — compute, storage, databases, networking, identity, observability, cost tools, and more — across Google Cloud, AWS, and Azure. Click any column header to sort — click again to reverse the order. For a full worked architecture using many of these services together, see the GCP, AWS, and Azure tutorial pages.

Component / Feature / ServiceGCPAWSAzure
Virtual Machines (IaaS Compute) Compute Engine — custom machine types, per-second billing, live migration keeps VMs running through host maintenance without a reboot EC2 — the largest instance-family selection of any provider, Spot/Reserved/Savings Plans pricing tiers, the broadest AMI/marketplace ecosystem Virtual Machines — tightest licensing integration for Windows Server/SQL Server, Azure Hybrid Benefit reuses existing on-prem licenses
Managed Kubernetes GKE — the first managed Kubernetes offering (2015); Autopilot mode bills per-pod resource request instead of per-node, removing node-level over-provisioning EKS — managed control plane, worker nodes on EC2 or Fargate, the deepest IAM/VPC CNI integration of the three AKS — free control plane (no per-cluster management fee), tightest integration with Microsoft Entra ID RBAC and Azure Policy
Serverless Containers Cloud Run — fully managed, scale-to-zero, request-based billing, built on Knative App Runner (closest Cloud Run analog) / Fargate (removes node management within ECS or EKS) Container Apps — built on KEDA, Dapr, and Envoy; scale-to-zero, purpose-built for microservices
Serverless Functions (FaaS) Cloud Functions (2nd gen, built on top of Cloud Run under the hood) Lambda — the original FaaS product, the broadest event-source integration of any provider, up to 15-minute execution timeout Azure Functions — Durable Functions extension adds stateful orchestration, deep native integration with Logic Apps
Object Storage Cloud Storage — a single namespace spanning Standard/Nearline/Coldline/Archive classes with strong global consistency S3 — the original and most mature object store; Intelligent-Tiering and S3 Object Lock (WORM) for compliance Blob Storage — Hot/Cool/Cold/Archive tiers; native Data Lake Storage Gen2 hierarchical namespace for analytics workloads
Block Storage Persistent Disk / Hyperdisk — network-attached, decoupled from VM lifecycle, optional regional (synchronously replicated) disks EBS — gp3/io2 volume types, point-in-time snapshots to S3 Managed Disks — Standard/Premium/Ultra tiers, encryption via platform-managed or customer-managed keys
Managed File Storage (NFS / SMB) Filestore EFS (NFS) and FSx (Windows File Server, Lustre, NetApp ONTAP) Azure Files (SMB and NFS protocols)
Managed Relational Database Cloud SQL (MySQL, PostgreSQL, SQL Server) — regional HA with automatic failover, read replicas RDS — the broadest engine selection, plus Aurora (MySQL/PostgreSQL-compatible, storage auto-scales, sub-30-second failover) Azure SQL Database / Database for PostgreSQL & MySQL — Hyperscale tier decouples compute and storage scaling independently
Globally Distributed, Strongly Consistent Database Cloud Spanner — synchronous global replication via TrueTime, external consistency, horizontally scalable with full SQL semantics Aurora Global Database — asynchronous cross-region replication, typically under 1 second of lag; DynamoDB Global Tables for multi-region NoSQL Cosmos DB — five tunable consistency levels (Strong, Bounded Staleness, Session, Consistent Prefix, Eventual), multi-region active-active writes
Managed NoSQL (Key-Value / Document) Firestore (document) / Bigtable (wide-column, huge-scale operational + analytical) DynamoDB — single-digit-millisecond latency at virtually unlimited scale, on-demand or provisioned capacity modes Cosmos DB — multi-model (Core/SQL, MongoDB, Cassandra, Table, and Gremlin APIs) in one service
In-Memory Cache Memorystore (Redis and Memcached) ElastiCache (Redis and Memcached) Azure Cache for Redis
Data Warehouse BigQuery — serverless, separates storage from compute, pay-per-query or flat-rate slot pricing Redshift — provisioned or serverless, tight integration with S3/Spectrum for querying data-lake files in place Synapse Analytics — unifies data warehousing, big-data Spark pools, and pipelines in a single workspace
Big Data / Distributed Processing Dataproc (managed Spark/Hadoop), Dataflow (managed Apache Beam, unified batch and streaming) EMR (managed Spark, Hadoop, Presto/Trino) HDInsight / Azure Databricks — first-party, co-engineered Databricks integration unique to Azure
Message Queue Cloud Tasks (point-to-point queues); Pub/Sub doubles as a queue for many use cases SQS — Standard (at-least-once) and FIFO (exactly-once, ordered) queue types Service Bus — queues plus topics/subscriptions, sessions, and dead-lettering built in natively
Pub/Sub & Event Streaming Pub/Sub — global scope, automatic scaling, at-least-once delivery with an optional exactly-once mode SNS (pub/sub fan-out) + Kinesis Data Streams (ordered, replayable stream) Event Hubs — Kafka-protocol-compatible ingestion at massive scale, easing lift-and-shift from self-managed Kafka
Event Routing / Event Bus Eventarc — routes events from 90+ Google Cloud sources to Cloud Run, GKE, or Cloud Functions EventBridge — built-in schema registry, third-party SaaS event sources, rule-based routing Event Grid — reactive, push-based routing with native Azure resource event sources
Global Load Balancing Global External HTTPS Load Balancer — a single anycast IP fronts every region, no DNS-based failover needed Global Accelerator (anycast IP) layered on top of Route 53 latency/geoproximity routing across regional ALBs/NLBs Azure Front Door — integrates global load balancing, CDN, and WAF into one product
Content Delivery Network (CDN) Cloud CDN (integrates directly with the Global External HTTPS Load Balancer) CloudFront Front Door's built-in CDN capability, or standalone Azure CDN
DNS Cloud DNS Route 53 — also performs health-check-driven failover routing Azure DNS
Virtual Networking (VPC) VPC — globally scoped by default; a single VPC can natively span every region without peering VPC — regionally scoped; VPC Peering or Transit Gateway needed to connect across regions/accounts Virtual Network (VNet) — regionally scoped; VNet Peering or Virtual WAN for global topologies
Web Application Firewall (WAF) Cloud Armor AWS WAF, paired with Shield for DDoS protection WAF built into Front Door / Application Gateway with managed rule sets
Identity & Access Management (IAM) Cloud IAM — permissions inherited down a resource hierarchy (Organization → Folder → Project), custom roles IAM — JSON policy documents, the finest-grained permission model of the three, IAM Roles for service-to-service auth Microsoft Entra ID (formerly Azure Active Directory) + Azure RBAC — the deepest enterprise-identity and hybrid on-prem AD integration
Workload Identity (no static credentials) Workload Identity Federation IAM Roles for Service Accounts (IRSA) on EKS, or task IAM roles on ECS/Fargate Managed Identities
Secrets Management Secret Manager Secrets Manager (automatic rotation) or the lower-cost Systems Manager Parameter Store Key Vault — secrets, keys, and certificates unified in one service
Key Management / Encryption Cloud KMS — customer-managed (CMEK) and customer-supplied keys, external key manager integration KMS — customer-managed keys (CMKs); CloudHSM for dedicated hardware-backed keys Key Vault, with a Managed HSM tier for dedicated hardware-backed keys
Monitoring / Metrics Cloud Monitoring — dashboards, uptime checks, SLO-based alerting policies CloudWatch — metrics, alarms, dashboards, anomaly detection Azure Monitor — metrics, Log Analytics, and alert rules unified under one umbrella product
Centralized Logging Cloud Logging CloudWatch Logs Log Analytics workspaces, queried with KQL (Kusto Query Language)
Distributed Tracing / APM Cloud Trace, paired with Cloud Profiler for continuous production profiling X-Ray Application Insights (part of Azure Monitor)
CI/CD (first-party) Cloud Build / Cloud Deploy CodePipeline, CodeBuild, CodeDeploy Azure Pipelines (Azure DevOps), with deep native GitHub Actions integration post-GitHub acquisition
Infrastructure as Code (first-party) Deployment Manager (legacy; Terraform is the de facto standard in practice) CloudFormation — also the underlying engine behind the AWS CDK ARM templates / Bicep (Bicep is the modern, more ergonomic DSL that compiles down to ARM JSON)
Container Registry Artifact Registry (successor to the older Container Registry) Elastic Container Registry (ECR) Azure Container Registry (ACR)
API Gateway API Gateway, or Apigee for full API lifecycle management API Gateway API Management
Cost Management Cloud Billing reports + the CUD Recommender, which can cut compute costs up to 57% (1-yr) or 70% (3-yr); commitment sharing across projects has been on by default since June 2026 Cost Explorer (AI-powered 18-month forecasts as of November 2025) + Compute Optimizer + Trusted Advisor, consolidated into the Cost Optimization Hub Microsoft Cost Management + Azure Advisor for right-sizing and reserved-capacity / savings-plan recommendations
Managed AI / ML Platform Vertex AI — unified ML platform with first-party access to Google's Gemini models SageMaker — unified ML platform; Bedrock for first-party access to foundation models, including Claude Azure Machine Learning + Azure AI Foundry — first-party access to OpenAI models via the Azure OpenAI Service
Hybrid / On-Premises Connectivity Cloud Interconnect (dedicated) / Cloud VPN Direct Connect / Site-to-Site VPN ExpressRoute — widely regarded as the deepest hybrid story, reflecting Azure's Windows Server/Active Directory heritage
Backup & Disaster Recovery Backup and DR Service AWS Backup — centralized backup policy spanning many services Azure Backup, plus Azure Site Recovery — a dedicated DR-orchestration product with no direct GCP/AWS equivalent
How to use this table in an interview
Memorizing exact service names is far less valuable than being able to reason about the underlying trade-off each row represents. When asked "which cloud would you pick," the strongest answers name the specific capability that matters most for the stated requirement — Spanner's synchronous global consistency for a "never lose a transaction across regions" requirement, Cosmos DB's tunable consistency levels when different data types need different guarantees, or AWS's sheer service breadth and hiring-pool depth when speed of hiring and ecosystem maturity matter more than any single feature. See the GCP, AWS, and Azure pages for a full worked example that ties many of these rows together into one architecture.
